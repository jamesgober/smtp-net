# smtp-net v0.3.0 - Core

**Date:** 2026-11-04
**Compare:** [`v0.2.0...v0.3.0`](https://github.com/jamesgober/smtp-net/compare/v0.2.0...v0.3.0)

**Messages, the sans-IO session, and local submission.** v0.3.0 was the first release that sends mail: it built standards-compliant MIME messages, spoke SMTP through a sans-IO state machine, and submitted to a mail server on the same machine (for example cPanel's Exim on `127.0.0.1:25`), with every failure classified as temporary or permanent.

## What's in 0.3.0

- **One call.** `Message::text` and `Message::html` built a message; `send_local` and `send` submitted it. The `Report` named the `Message-ID`, the accepted and refused recipients, and the final reply.
- **Messages.** The builder covered text, HTML, attachments, and inline images (nested mixed > related > alternative), chose 7bit, quoted-printable, or base64 per part (7-bit clean output by default, so DKIM signatures survive relays later), encoded non-ASCII subjects and display names as RFC 2047 words through parse-net, wrote RFC 2231 file names, and generated `Message-ID` and `Date`. Every setter refused CR, LF, NUL, and other control characters with the field and position named; nothing was stripped. Bcc recipients went into the envelope only.
- **The session.** A sans-IO state machine for the greeting, EHLO (HELO only on verified loopback plaintext), STARTTLS (sent only when advertised, with the response-injection check after the `220`), MAIL, RCPT, DATA with streaming dot-stuffing correct across every chunk boundary, RSET, NOOP, and QUIT. PIPELINING sent MAIL, RCPT, and DATA as one group of at most 4 KiB; SIZE, 8BITMIME, and SMTPUTF8 were checked before MAIL; enhanced status codes were parsed. Deadlines followed RFC 5321 4.5.3.2.
- **Failure classification.** Every error carried a disposition (temporary or permanent) and `possibly_delivered`, set when the connection was lost after the end of the data was written and before its reply was read, so a retry could be flagged as a possible duplicate.
- **The blocking driver.** `Client` reused one connection for many messages, with idle and per-connection limits and one transparent reconnect when the server had closed an idle connection. Plaintext went only to a peer whose address was confirmed loopback.
- **Raw messages.** `PreparedMessage::from_raw` accepted RFC 5322 bytes built elsewhere after refusing bare CR and bare LF (the SMTP smuggling sequences), lines over 998 octets, and messages without a header block or From.
- **Test support** (feature `testing`). `TestServer` was a loopback SMTP server with fault injection (closes, delays, malformed and oversized replies, refused recipients, slow drip); `ScriptedServer` played conversation transcripts against a session.

## Verification

- 39 conversation transcripts, each run whole and with server and client bytes split into pieces of 1 to 16 octets.
- 24 driver tests against `TestServer`, including a connection cut after the end of the data (possibly delivered), a slow drip (stage timeout), a reply flood (budget), and plaintext to a remote host (refused).
- Property tests for addresses, message output (CRLF only, lines within 998, no Bcc, exact `encoded_len`), quoted-printable and base64 round trips, encoded words, the reply parser at any split, and dot-stuffing at any split.
- Counting-allocator tests: the body path, replies before the end of data, the encoders, the header gate, and `write_to` into a sized buffer allocated nothing. A text plus HTML build allocated 97 times; the 0.6 milestone owns that number (target at most 8).
- Eight fuzz targets (reply, EHLO, session, address, content type, header value, raw message, transcript).
- CI: Linux, macOS, Windows on stable and 1.85; a `no_std` build on `thumbv7em-none-eabi`; an interop job sending every message shape to Mailpit and Exim; a check that the runtime tree holds only first-party crates.

## What's next

`0.4.0`: STARTTLS and implicit TLS in the driver through the `TlsConnector` seam, AUTH PLAIN and LOGIN, CHUNKING, DSN, the too-many-recipients deferral, the `SendGate` pacing hook with `HourlyLimit`, and the checksummed job payload.
