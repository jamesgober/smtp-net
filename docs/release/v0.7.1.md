# smtp-net v0.7.1 - Platform notes

**Date:** 2026-11-09
**Compare:** [`v0.7.0...v0.7.1`](https://github.com/jamesgober/smtp-net/compare/v0.7.0...v0.7.1)

**Platform notes, and two fixes found while checking them.** The new [`docs/PLATFORM-NOTES.md`](../PLATFORM-NOTES.md) covers what differs between Linux, macOS, and Windows. Checking each claim against the code and the machine found two defects, both fixed here with a test that failed first. smtp-net also moves to net-io 0.7.1 and tls-net 0.9.0. There is no API change.

## Fixed

- **Connecting to `localhost` on Windows took 1 second.** Windows resolves `localhost` to `::1` first and retries a refused connect for about 2 seconds. With the 2-second local connect timeout shared between the two addresses, every connect to `localhost` on a server listening on `127.0.0.1` only waited out the IPv6 attempt: 1.03 s measured. The addresses now race (RFC 8305), and the IPv4 attempt starts 100 ms after the first for a loopback host, so three connects take 0.51 s in all. For other hosts the next address starts after 250 ms, so a relay with broken IPv6 no longer costs a whole attempt either. The loopback check for plaintext still applies to whichever address wins (D-107).
- **`DomainLimit` could lose a count after the clock stepped back.** After a wall-clock step back of 65 minutes or more, a new count could reset the slot holding a newer one, and the domain could then take more than its budget. The newer count is kept now, as `HourlyLimit` already did (D-106).

## Added

- `docs/PLATFORM-NOTES.md`: build needs per feature set, how `localhost` resolves and what a refused connect costs on each platform (measured), trust anchors, which clock each part uses and what a clock step does, and the random source per platform.

## Changed

- net-io 0.7.1 (from 0.6.1) and tls-net 0.9.0 (from 0.5). For smtp-net's blocking client the fix that matters is net-io's: on Windows, a process whose threads ended after using a connection could freeze (a pool fed by short-lived threads, for example). The other net-io fixes are in its reactor, which smtp-net does not use (D-105).
- Connects race the resolved addresses, as above.

## Verification

- Every test, on Linux, macOS, and Windows, stable and 1.85. New: `test_localhost_connects_quickly_when_the_server_listens_on_ipv4_only`, `test_clock_going_backwards_keeps_every_count` (`DomainLimit`), and `test_clock_jumping_forward_retires_the_window` (`HourlyLimit`).
