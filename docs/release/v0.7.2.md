# smtp-net v0.7.2 - Security fix

**Date:** 2026-11-11
**Compare:** [`v0.7.1...v0.7.2`](https://github.com/jamesgober/smtp-net/compare/v0.7.1...v0.7.2)

**A failed transaction could leave commands queued on a pooled connection; the connection is now reset or discarded.** Versions 0.4.0 to 0.7.1 are affected when an application sets DSN parameters on an envelope (`Envelope::dsn`). Upgrade; 0.7.0 and 0.7.1 are yanked. There is no API change beyond two new error variants.

## Fixed

- **A refused send could add its recipients to the next message on the connection.** With DSN on, each RCPT line carries `NOTIFY` and `ORCPT` with the whole address, and a long enough address puts the line over the 512-octet limit of RFC 5321 4.5.3.1.4. `Session::begin` refused that line, but the MAIL line and any earlier RCPT lines of the same pipelined group were already queued, and they stayed queued. The `Client`, and a `Pool` through it, then reused the connection, and the next message went out behind them. A server that keeps the open transaction when a second MAIL arrives (Postfix answers `503 5.5.1` and keeps it) added the next message's recipients to the stale transaction and delivered the next message to both sets of recipients, while the client matched the `503` to its own MAIL and reported the message failed. With DATA instead of CHUNKING, an empty message went to both sets.

  Now:
  - `begin` formats every MAIL and RCPT line of the transaction before it queues the first, so a line that cannot be sent is refused with nothing queued. If queuing still fails, the output and the expected replies are restored.
  - A refusal after the server holds an open transaction closes the session.
  - `Client::is_open` is true only when the session is ready with nothing queued and no reply outstanding, so neither `Client` nor `Pool` reuses any other connection, and QUIT is never sent behind queued commands; such a connection is dropped.
  - The refusal is the new `Build(CommandTooLong)`, permanent, instead of `Usage(Closed)` ("the session is closed"), which was wrong.

## Changed

- New `BuildError::CommandTooLong` and `BuildError::CommandHasControl` (the last check for CR, LF, or NUL in a command line, which validated types cannot produce). `BuildError` is `#[non_exhaustive]`, so this is not a breaking change.
- `TestServer` answers a MAIL inside an open transaction with `503 5.5.1 nested MAIL command` and keeps the transaction, as Postfix does, so a test against it catches a client that leaves commands queued. Before, it reset the transaction on every MAIL, which is why the suite did not catch this.
- DSN parameters (ENVID and ORCPT) are written as xtext straight into the command line, so `Session::begin` allocates nothing with DSN either.

## Cost

Each MAIL and RCPT line is formatted twice, about 40 ns per line (an estimate, to be measured in 0.9 on a quiet machine), with no allocation. A connection left unclean by an error is dropped without QUIT.

## Verification

- Every test on Linux, macOS, and Windows, stable and 1.85. New: `tests/crosstalk.rs` (through `Client` and `Pool`, with CHUNKING and with DATA, and the `TestServer` nested-MAIL model), `test_begin_refusing_a_long_rcpt_queues_nothing`, `test_begin_refusing_a_long_mail_line_queues_nothing`, `test_dsn_parameters_are_written_as_xtext_into_the_line`, and `test_begin_with_dsn_parameters_allocates_nothing`.
- The crosstalk tests fail on 0.7.1: the reset message reaches the earlier recipient.
- Fuzz targets built, loom models passed, `cargo deny` and `cargo audit` clean, `cargo package` from a fresh target directory.
