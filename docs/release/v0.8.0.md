# smtp-net v0.8.0 - Simpler API

**Date:** 2026-11-11
**Compare:** [`v0.7.1...v0.8.0`](https://github.com/jamesgober/smtp-net/compare/v0.7.1...v0.8.0)

**The first alpha release: the same features, with the API simplified before the field test.** A review of every public item against four rules (a one- or two-line send, plain names, one way to do each thing, a complete API reference) found eleven problems, recorded in [`dev/SIMPLICITY-AUDIT.md`](../../dev/SIMPLICITY-AUDIT.md). This release fixes all of them. Most fixes are renames or moves, and the table below maps every 0.7 name to its 0.8 replacement. One of them is a defect: through the count-based `SendGate::admit`, a `DomainLimit` admitted every message. Wire behaviour, message bytes, and performance are unchanged.

A gate written for 0.7 that counted recipients reads them from the envelope now:

```rust
use smtp_net::{Admission, Envelope, SendGate};
struct Shared(std::sync::Arc<smtp_net::HourlyLimit>);
impl SendGate for Shared {
    fn admit(&self, envelope: &Envelope, now_unix_ms: u64) -> Admission {
        self.0.admit(envelope, now_unix_ms) // was: self.0.admit(recipients, now_unix_ms)
    }
    fn refund(&self, envelope: &Envelope, now_unix_ms: u64) {
        self.0.refund(envelope, now_unix_ms)
    }
}
```

## Fixed

- **A `DomainLimit` reached through the count-based `SendGate::admit` admitted every message.** A count carries no domains, so the method had nothing to check. The client used the envelope methods and was not affected, but a caller or a combinator that used the count method got no per-domain limit, and nothing warned it. `SendGate` now has one pair of methods, and both take the envelope (D-111).

## Changed

- The crate root keeps what an application uses. The sans-IO core moved to `smtp_net::protocol`, MIME parts, encoders, sinks, and randomness to `smtp_net::mime`, the canonicalizers to `smtp_net::dkim`, and test support to `smtp_net::testing`. Each item has one path (D-110).
- One method per job: `ServerBuilder::tls` takes any `TlsConnector` (D-112); `Message::prepare_signed` is gone in favour of `prepare()?.sign(..)` (D-113).
- Plain and consistent names: `PORT_STARTTLS` and `PORT_IMPLICIT_TLS` (D-115); `with_` setters on `Dsn` and `Envelope`, with getters that carry the field's name (D-116); `DomainLimit::recipients`, `ReplyCode::is_temporary`, `QuotedPrintableState` (D-117).
- The `ServerBuilder` chain never stops for a `Result`: `mechanisms` and `client_name(&str)` are checked by `build()` (D-118).
- `docs/API.md` was rewritten as a task-oriented reference of every public item. Its examples and the README's compile and run as doctests (D-110).

## Added

- `RejectedRecipient`, the one shape of a refused recipient in a `Report` and in an `Error` (D-114).
- `ClientName::parse` for a domain, an IP address, or an RFC 5321 literal; `ConfigError::InvalidClientName` (D-118).
- `dev/SIMPLICITY-AUDIT.md`: the findings, what was kept and why, and what the change touches.

## Verification

- Every test on Linux, macOS, and Windows, stable and 1.85, and 104 doctests including every example in `docs/API.md` and the README. New tests: `test_client_name_parse_accepts_names_and_addresses`, `test_client_name_parse_refuses_bad_literals_and_names`, `test_parsed_client_name_formats_as_ehlo_argument`, `test_domain_limit_behind_a_trait_object_still_counts_per_domain`, `test_client_name_is_checked_by_build_and_sent_in_ehlo`, `test_mechanism_list_is_checked_by_build`, `test_rejected_recipient_accessors_agree_with_the_error`.
- Uncontended `HourlyLimit` admission, 0.8.0 against 0.7.1 on Linux, alternating builds under a load average of 45 to 72: 83.4 ns against 84.2 ns, then 64.4 ns against 61.6 ns, level within noise (D-111). The 30 ns figure in `docs/PERFORMANCE.md` was measured on a quiet machine, and 0.9 re-measures it the same way.
- Fuzz targets built, loom models passed, `cargo deny` and `cargo audit` clean, `cargo package` from a fresh target directory.
